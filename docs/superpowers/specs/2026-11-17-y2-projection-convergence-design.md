# Y2 投影消费收口 设计 spec

> 范围：A 类单独立项。四步按序做在同一分支，每步有独立出口，四步一起部署——第③步（翻禁+版本 4）单独上线时画面主槽为空，禁止单独部署。依据=总目录 v11 Y2 行 + 裁决 A1 / C1 / C3 / C5 / D3 / D6 / E67 + 本文对现库的复核。
> 开发测试档无用户画布需要保留。禁止 normalizer、双键读、影子双跑、版本分支、以及「先留着以后再删」的垫片。

## 0 本文解决什么

画布的作者态在 Y.Doc，执行态在 RuntimeEvent，渲染必须是纯函数。现在渲染仍由 `applyDocToStore` 全量灌进 zustand，再由 `reconcileGroupGeometry` 把 store 与 doc 仲裁回同一套坐标。主槽 `fileId` 与执行态 `status` 仍写在 doc 里，而 `frame-deny` 对 `server-forbidden` 只登记、不拒绝。Y2 把这三件事收成一条链：schema 4 只接受作者键，`projectCanvas` 是唯一渲染出口，主槽由唯一解析函数裁决，节点状态与产物从运行时投影读，余额仍走现有 socket。

## 1 目标 / 非目标 / 反目标

**目标**

1. 协议与 doc 版本 3→4 硬切。主槽作者键为 `mediaId`。`server-forbidden` 全键族在 L1 与 L2 都拒绝。
2. `projectCanvas` 成为主画布唯一渲染出口。`reconcileGroupGeometry` 生产调用为 0。帧算法仍是 `deriveGroupFrame`。
3. 主槽显示与上游注入由全仓唯一的 `resolvePrimaryMediaId` 裁决（D8）。节点上的执行状态与产物从 `RuntimeProjection` 读。余额继续从 socket 的 credits 对象读，留到 Y3。

**非目标**

- 不删 `/execution`，不把余额改成 REST（Y3）。
- 不重写 14 处复合写路径为 intent-first（桥保留，见 D2）。
- 不改对象删除面的引用计数（跨团队粘贴改为字节拷贝，避免踩现行删除面，见 D5）。
- 不恢复单人团队的 awareness 广播。
- 不新建名为 CopyMedia 的路由。仓内无此 API。
- 不收口付费冻结请求的**胜臂**重放（`settleForExecutionRequestItem` 不写意图行 creditsConsumed——本批只短路作废精确键，见 D8）。
- 不改同团队跨项目共享行的删除面连坐语义（源项目销毁=另一项目同 Media 行失效——本批明确不碰，见 D5）。

**反目标**（做成了也算失败）

- 为 schema 3 文档写键重命名器，或读路径同时认 `fileId` 与 `mediaId`。
- 再实现一套组帧公式，使公开页与主画布各算各的。
- 主槽出现第二份判定逻辑（画面、格子、缩略图、上游各算各的）。
- 删掉 reconcile 之后，diff 桥继续把派生宽高、hidden、相对坐标写回 doc 当权威。
- 跨团队粘贴把源团队的对象键挂到目标团队的新 Media 行上；或新行在任何窗口内处于零护栏状态（护栏形态=pending 行+同事务预留，见 D5）。
- 任何时刻把对方团队的 media id 写进 doc「图先显示着」——包括命令在途的乐观形态。

## 3 方案与终裁

### D1 投影形态：复用派生内核，主画布只做装配

考虑过两形态。

- 独立再写一套帧算法。公开页与主画布会分叉，直接违反 C1 的单源。否决。
- `projectCanvas` = `deriveRenderCanvas(readModel)` 的结果，再叠覆盖。帧与 hidden 剔除仍由共享内核完成。采用。

落点在 `apps/web`。签名：

```ts
projectCanvas(input: {
  readModel: { records: readonly RenderSourceNode[]; edges?: readonly RenderSourceEdge[] };
  runtime: RuntimeProjection | null;
  mediaFacts: ReadonlyMap<string, MediaFact>;
  gesture: ReadonlyMap<string, GestureOverlay>;
  localPreview: ReadonlyMap<string, string>;   // 节点 id → blob URL（粘贴本地预览——只在解析为空时显示）
}): { nodes: RenderNode[]; edges: RenderEdge[] }
```

装配顺序固定：

1. **墓碑前置剔除**：先从记录副本去掉活动墓碑（谓词=现有 `isActiveTombstone`，不重写——吃运行时条目非 doc 记录，`composeRenderModel` 现行次序就是进合成前丢整节点），再把剩余记录送进内核。死节点不进内核，才不会撑大 auto 组帧、不会留在 cellNodes 里。对着墓碑节点的手势项不折入。悬空边由内核既有过滤去掉。
2. **gesture 折进记录再进内核**。叶子/顶层节点：会话中的 position / width / height 折入 records 副本。正在 resize 的组：该会话矩形作为该组的 `liveFrame` 传入 `deriveGroupFrame`——`deriveRenderCanvas` 增加这个可选入参（按组 id 索引；公开页不传，恒 undefined）。内核现行语义即所需：`liveFrame` 只被 manual/storyboard 值面消费、auto 恒派生——后贴的宽高不进组帧，storyboard 预览尺寸只认 liveFrame。禁止在内核输出之上叠一层「手势帧改写」——rel、hidden、cellNodes 都必须带着手势一次性算出。
3. `deriveRenderCanvas` 产出几何、rel、hidden 剔除、边过滤、cellNodes。
4. **执行覆盖（主槽与状态走 D8 解析）**：显示用媒体 id=「作者键 `data.mediaId` 非空用它，否则运行时产物」（第①步实现过渡期暂读 `data.fileId` 同优先序——B3 写者换键时同步切 `mediaId`，spec 与 plan 同轨的登记过渡）；`execStatus` 只来自投影。**localPreview 只在 `resolvePrimaryMediaId` 为空时**盖住画面（粘贴本地预览——复制者本会话已拿到的字节；不进作者缓存、不进 diff、不把对方团队 media id 写进 doc，命令失败或槽被占时清掉）。这条覆盖要**写进 cellNodes**——分镜子被 hidden 剔除、不在 React Flow 节点列表里，而内核产出的格子只有 id/thumbnailUrl/slot：执行覆盖必须**按格子 id 回到剔除前的作者记录**上取 `data.mediaId`/产物再写进 cellNodes——只遍历 React Flow 输出节点，格子是空的。主画布分镜改为只消费这份 cellNodes（删除 GroupNode 现行的 store 二次扫描——见第①步）；`CellNodeInfo.fileId` 改名 `mediaId`。doc 里不出现 `status` / `fileId`。
5. `mediaFacts` 只提供尺寸等事实，不改作者坐标，不写 doc。载体=既有 media-facts 批量通道与产物事件定向拉取（`mediaFactsRuntime` / `dispatchRuntimeArtifacts` sink），按 `mediaId` 取当前态；`factVersion` 是 Media 行全局单调计数快照（`schema.prisma:325`）、跨 factType 不可比——增量同步沿用既有定向拉取，本批不新造版本协议。

`localCollapsed`（viewer 本地折叠 override）今天就不进隐藏判定（`deriveHiddenMap` 只吃 doc data），本批不把它塞进 `projectCanvas`——组壳的折叠属性继续读它。

`composeRenderFromNodeStore` 随第①步删除。公开页继续直接调用 `deriveRenderCanvas`（现行锚：`ProcessSnapshot.tsx:87`），不走 `projectCanvas`（也不传 gesture/localPreview）。

**等价域**（对拍锚，写进测试名）：`gesture` 为空、`runtime` 为空、`mediaFacts` 为空、`localPreview` 为空、liveFrame 不传时，`projectCanvas` 的节点几何、parent、hidden 剔除、边集与 `deriveRenderCanvas` 逐位相等。运行时状态、手势与本地预览不在这个等式里。

### D2 两份数据：作者缓存与渲染列表分开，桥只读作者缓存

`deriveRenderCanvas` 的输出是相对坐标，且不含分镜子与折叠子节点（dropped 集）。v1 的「store 持久域 = projectCanvas 输出」与「diff 只翻译作者字段」不能同时成立：store 若等于投影，下一轮 diff 会把隐藏子节点编成删除、把相对坐标当绝对坐标写回。采用两份数据：

- **作者缓存 = doc 读模型**：全部节点（含隐藏节点）、绝对坐标、parent、作者 data、边。`dispatchProjectionDiff` 只读这份。持久化出口继续用现成的 `toDocRecords` → `applyKeySetTable`，不另写一套剥键。**store 管线**：`nodes` 继续作为作者缓存——diff 桥、组缩放的最小尺寸（`calcGroupMinSize` 读绝对坐标）、组渲染的 data 面都继续读它；React Flow 改接画布状态上另一份渲染列表（`renderNodes`，命名实现者定），`CanvasView` 不再把 `nodes` 直接交给 ReactFlow。**作者缓存与渲染列表放同一次 zustand `set`**（D3 单键 setState=1 纪律；v2.11 钉死计数口径=**一次本地作者事务 `useCanvasStore.setState` 恰 1 次**——`nodeStore.nodes` 由**同一份 `toReadModel(doc)` 快照在同一同步函数里更新**，四节点组件〔ImageGenNode/VideoGenNode/AudioGenNode/MultiImageNode〕与六个配置面板仍订阅 `useNodeStore` 的 `nodes`，本批不迁移订阅者；ns 重建对未变节点沿用旧对象引用——照渲染列表身份复用同款，防每笔本地事务全量组件重渲染；本地作者事务路径的 `bridgeToCanvasStore` cs 写退役，`updateConfig`/`updateMultiImageImages` 的自有 ns set+桥同批收敛进漏斗尾快照〔nodeStore:689-712/:813/:825〕）。
- **React Flow 列表 = `projectCanvas` 的输出**。只渲染，不进入 diff。可见集合由内核剔除承担——今天 `applyDocToStore` 里 `deriveHiddenMap` 写 `hidden:true` 属性+`edgeHidden` 的机制随出口换轨退役（行为等价），禁保留双轨。

无手势时：作者缓存等于 doc；渲染列表等于 `projectCanvas(作者缓存, 空覆盖)`。复合写桥降级为：操作先改作者缓存 → `diffProjectionToIntents` 只翻译**作者字段**（增删节点、parent、abs position、作者 data 键、边）→ `dispatchCanvasIntent` 单事务写入 doc → 立刻用 `projectCanvas` 重填渲染列表。

diff **不得**把派生宽高、hidden、相对坐标编成 intent。组帧键规则=现行键集表，一字不改：auto/collapsed 组零帧键（**含 position**——v1「auto 组也持久 position」撤回，它会给 auto 组造出派生+持久两个原点）；storyboard 组只留 position；manual 组留宽高；「最后一名成员离开」时 `emptyGroupSealFrame` 保留，把当时的原点封成 manual 帧（`canvasStore.ts:1670` 现行语义）。

桥内删除：

- `dispatchProjectionDiff` 首行的 `reconcileGroupGeometry(doc, 'cs')`。
- `dispatchCanvasIntent` 尾的 `reconcileGroupGeometry(doc, 'doc')`。

同批删除的仲裁零件，不是另开卡：让位账本、`RECONCILE_EPS`、ratchet、`geometryTrap`、`assertReconcileSingleWriterWindow`、`reapplyGestureProtection`。四件前置按这个顺序做，避免假绿：

1. 先把假门禁改成会失败的测试（`geometryTrap` 只计数不抛、单写者窗口恒真），再删实现。
2. census 从「生产调用恰 4」改为「生产调用恰 0」，`ALLOW_FN` 白名单去掉 reconcile。
3. 现有几何测试改为对 `projectCanvas` 与 `deriveRenderCanvas` 对拍。禁止为了让旧测试编译而保留 reconcile 生产包装。
4. 字段闭环门禁（E17）与投影不变量改为新形态：doc 组记录零派生帧键；无手势会话时作者缓存≡doc 读模型、渲染列表≡`projectCanvas(作者缓存, 空覆盖)`。

同名异构点名：`projectCanvasNodes`（`apps/web/src/utils/`）是 doc 写入前的 EPHEMERAL 剥键适配（投影快照与漏斗入口共用），与本批的 `projectCanvas` 不是同一个函数，第①步不删。

新不变量见 §5-5。

### D3 增量：全量投影 + 逐字段对象身份复用

子节点一移动，auto 组的原点就变，兄弟节点的相对坐标一起变；折叠或分镜开关改变整棵子树的 hidden。v1 的「脏 id 加祖先组」重算集不含兄弟，必留过期几何——等于在 `deriveRenderCanvas` 旁边再写一套帧算法。否决。采用：

- 每次 doc 批次（`observeDeep` 事件批）都对**完整作者记录**调用 `deriveRenderCanvas`。
- 与上一帧输出逐字段比较：相等的节点复用原对象，输出数组浅建。仅变化项换新对象。**身份复用发生在执行覆盖写完之后**——比较对象是上一帧**最终渲染对象**（含写进 cellNodes 的覆盖）；格子内容未变时组节点复用上一帧对象，包括原来的 cellNodes 引用。
- 边的 `observeDeep` 与节点分开（现行即两个独立注册）：只改边时重跑边过滤，节点对象能复用则复用。
- 时序：远端=idle 50ms，自本轮第一个脏事件起 max-wait 200ms；本地作者事务=同步投影、不进去抖，**并取消尚未触发的远端定时器**。同步投影读的是这笔事务之后的 `toReadModel(doc)`，同时写作者缓存与渲染列表（同一次 zustand `set`）——读滞后的 zustand 再去取消定时器，会丢掉已经进文档、还没进 store 的远端更新（基线注记：现 `onRemote` 已对本地 origin 短路返回，但短路不 cancel 已挂定时器——本批补上）。

验收：单键编辑触发的 React 状态更新次数为 1（计数范围=`useCanvasStore.setState`——v2.11；nodeStore 同快照同步更新不计入）；未编辑节点的对象身份不变（身份复用比较的对象是**上一帧最终渲染对象**的值，不是内核当次新分配的对象）。夹具不少于 200 个节点且含一个分镜组；格子内容未变时，该组节点对象必须被复用。不设绝对毫秒门槛；同一次测试里，带复用的投影必须短于同夹具的**全量重建对照**（`applyDocToStore` 删除后以测试内等价全量路径为对照——全量投影+全新对象的工作量口径），数字写在该测试里。

### D4 手势：预览在 overlay，提交是事务前判定 + 恰一次 doc 事务

拖动与组 resize 已是松手提交。缺口是叶子 resize 仍走 `resizePending` 逐帧落点。第①步把它收成同一会话：移动过程只写 `gesture` 表，doc 零写。

会话与提交点：pointerdown 时 `setPointerCapture`。提交点（任一到达即提交，一次性标志保证只提交一次）：pointerup、pointercancel、pagehide、`visibilitychange` 且 `document.hidden`。

不变量检查在生产环境同样执行，且**在打开事务之前**：对「意图应用后的作者记录」做纯函数判定。判定与 transact 在同一次同步调用里、中间没有 await；一次手势的所有脏节点同一次事务。Yjs 的 `transact` 内写操作即时生效、回调抛错不回滚已发生的写——检查放进事务是有窗形态。失败：不调用 transact，清掉 gesture，作者缓存与画布保持上一笔，经既有 `invariant_violation` 遥测通道上报（`collab-telemetry.ts` 十二值词表内）；不蒙层、不重试、不静默吞。成功：doc update 恰 1 次，然后清空 gesture，再用 `projectCanvas` 重填渲染列表。

硬崩溃丢掉进行中的手势，画布回到 doc 里的上一笔。接受（C2 已写明）。

### D5 跨团队粘贴：BindMedia 驻留会话写槽，拷贝占坑先行

项目只属于一个团队。跨团队粘贴不是「引用对方的 Media 行」。v2.1 的客户端回写有两个洞：Yjs map 后写获胜——命令在途时另一成员写入槽位，返回后的那一笔会盖掉他；客户端写回前崩溃——新 Media 行零护栏，对象与配额一起没。填槽收归服务端。现状锚（§2 表）都在这条命令与它的调用方上改，不新路由、不恢复 CloneBinding：

1. **客户端**：副本节点先写入 doc，槽上**没有媒体 id**。**命令体五字段**：`sourceProjectId`、`sourceNodeId`、`mediaId`（取当前画面的解析值：作者键非空用作者键，否则产物）、`targetNodeId`、`commandId`（客户端生成；`expectedRev` 已随 CAS 删除）——**幂等范围=「一个源媒体到一个目标节点」**，一次粘贴 N 个带媒体的节点就是 N 个 `commandId`。源 id 不进 doc。复制者屏幕上的预览来自本会话已拿到的字节，作为 `projectCanvas` 的 `localPreview`（节点 id→blob URL）——只在解析为空时显示（D1），命令失败或槽被占时清掉；不进作者缓存、不进 diff。客户端不发第二笔 `updateNodeData`；作者缓存与渲染列表同一次 zustand `set`。
2. **校验**（权限三查+源域）：调用者是**目标项目**的编辑；源 Media 存在、ACTIVE、未软删、**`size` 非空非零**（空值不得当 0 字节过配额门——直接拒绝）；调用者是**源 Media 所属团队**的成员（防凭 id 拿别队媒体）且**能读源项目**。源配对两腿改查**源项目**（现行两腿都查目标项目——§2 锚，跨项目源必 miss）：源上的 NodeArtifact 三维对齐（`sourceProjectId` 域），或源项目 doc 源节点引用兜底（词表六键后，doc 腿扫 `mediaId`）。
3. **同一团队**：不拷贝、不建行，返回原 id——「本行 id」即源 media id，走与跨团队**同一套三档**：驻留会话读槽，槽空才写原 id；槽=源 id（上次崩溃在写槽后）→只按全量快照补绑定；槽=其他 id→`409 SLOT_OCCUPIED`，**不调 deletePending、不删任何对象**（同团队没有新行没有新键）。两个项目共用一行 Media——源项目销毁会让这行失效（删除面连坐），本批明确不改。
4. **跨团队拷贝=占坑先行**（顺序钉死，S3 不进 PG 事务）。同一 `commandId` 的并发与重试按**槽上 id 三档**分诊——「槽被占」不是无条件档，后到请求看见的可能是本命令刚写上的 id：
   - **幂等查** `(teamId, bindCommandId)`：命中且 completed→返回已有 id，不再拷贝；命中且 pending→沿用行上新键继续（不走第二次占坑事务）；同一 `commandId` 的源媒体/源团队/目标项目任一不同→`409 BIND_COMMAND_MISMATCH`。唯一约束允许多 NULL，挡不住换源——比对是应用层判断，锚=行上 `bindSourceMediaId`/`bindTargetProjectId`/`teamId`。
   - **事务内占坑**：`assertCanUploadInTx(tx, 目标团队, Number(源.size))`（内部 `lockTeamQuota` 串行化+三段和 usage+ΣACTIVE 预留+incoming——**pending 行本身不在三段里，占坑就是这次同事务插入的 StorageReservation 行**，`upperBoundBytes=源.size`、`state=ACTIVE`、与 Media 行一对一），插入 **pending** Media 行（新键、`bindCommandId`、`bindSourceMediaId`、`bindTargetProjectId`、`pendingExpiresAt`），提交。`(teamId,bindCommandId)` 唯一冲突（并发同命令先提交）→**catch 在 `$transaction` 之外**（事务内 catch→aborted→重读 25P02 仍 500——§2 25P02 纪律锚），重读用新查询走幂等档。`size` 只在调用边界转 number，列保持 BigInt。
   - **同桶 CopyObject**（`minio.service` 新增方法，**用源行 `bucket` 列**）：按源键去重——`key`、非空 `thumbnailKey`、非空 `objectKey` 若指向同一对象，新行共用同一把新键；新键走现有 `buildKey`。**不建 ObjectManifest 行**——orphan 清扫只扫 manifest 行域（无全桶枚举），新键的清理锚=pending 行三键引用。**CopyObject 失败**：删掉本轮已拷出的新键（404 容忍），再 `deletePending`，不写槽。

## 8 留给实现者

- 增量夹具的节点数（≥200）与对照的具体口径写在第①步测试里，阈值不得宽于全量对照的量级。
- `gesture` 表与粘贴本地预览表（`localPreview`）放哪个模块，只要 `projectCanvas` 的 gesture/localPreview 参数是唯一读点、松手/命令终态清空、且都不写回 doc。
- 字节拷贝顺序钉死为「幂等查（含 409 两档）→事务内插 pending 行+预留 ACTIVE（唯一冲突→**事务外** catch、新查询重读幂等档）→CopyObject（源行 bucket 列、不建 manifest 行；失败=删本轮已拷键 404 容忍+deletePending）→withSession 同步条件写（槽上 id 三档）→projectBindings（delta=回调内快照返回值）→完成独立函数（CAS+SETTLED+factVersion+state fact）／槽=他 id 才删已拷新键+deletePending」，S3 不进 PG 事务；配额门=既有 `assertCanUploadInTx(tx, 目标团队, Number(源.size))`，占坑=同事务 StorageReservation，不另写公式。
- `resolvePrimaryMediaId` 的入参形态（node 数据+投影槽）由实现者定，但全仓消费面一个不漏：画面、cellNodes、`computeThumbnailUrls`、两处上游读点。`authorMediaId` 捕获点=**三路径受理**（enqueue 入队前同款节点集规则建 `job.data.authorSlots`=工作集上限/execute 开头 readCanvas 内存表/admitRequest plan 行两列），claim 插行落两列（ClaimInput 两列必填——四处调用方，两链受理读槽真值、B1~B2d 过渡占位除外）、**rearm〔FAILED/VOIDED/UNKNOWN 三态〕重写本次受理值**（takeover/same-job-alive 不写、禁按 result==='rearm' 补写）、完成只读列；冻结 JSON 不冗余。
- 完成时序三段单源：冻结/非冻结两条腿+reconcile 恢复链共用 `readAuthorSlot`/`releaseAuthorSlot`（CollabWritePort 两封闭操作；API 进程内直调；独立 worker 经 `x-worker-scope` HMAC 内部 POST——请求体只 intentRowId、execSeq 在 scope、服务端自装意图行核对项目/节点/代际、worker 不传 mediaId）；release 回调=现场=冻结值才删+快照收集作返回值、projectBindings 在返回之后 200 之前（projectBindings 失败同非 2xx；worker 拓扑下跑在 API 端点内——MediaBinding 写者白名单不动）；**读槽时点=provider outcome 返回后、finalize 调用前（execution 两支+两链 processor/consumer 完成点+恢复链同点；物化不读不释放）；release 调用点全族**——两 claim 回放臂+两链 controller `!created` 受理（作废键命中不带 fileId 不释放/未命中带 fileId+release）+四条新鲜 `outcome==='committed'` 出口（含两链完成点）+finalizeFromStage 恢复链（authorVoid 可选参数传入 commitImage，text 链及其它非画布调用点不传）；release 先于 emit done；**release 不进 commitImage/finalizeVideo/idempotentOutcome（五消费面）**；释放失败=AuthorSlotReleaseError 专型 catch 首位 re-throw（队列 moveToDelayed 不耗 attempts/同步 3 次→5xx/冻结链 item error→请求 FAILED；两链 processor/consumer 同构有上限重排、耗尽后对账补释放臂接管——v2.11）；闸序维持钉死（status∧execSeq 之后、creditsConsumed 合取之前）。
- 全量快照统一=写回调内 `collectMediaRefsForNode` 返回值；三处直调（粘贴写槽/执法删键/生成胜删键）与装入重扫段①同构，不得各写一份收集、不得写完另开 read 会话。
- 作废短路两处（idempotentOutcome+finalizeInTx）共用同一精确键构造函数（`author-void:{intentRowId}:{execSeq}`——等值查，禁前缀扫描）、同一回填源（按资金锚三元从已提升 Media 行）、同一闸序（status∧execSeq 之后、creditsConsumed 合取之前）；保留谓词两臂与作废行 30d 豁免随作废臂同 commit。
