# Spec: 扩展图片节点 (Image Extension Node)

> 日期: 2026-06-28
> 状态: 待确认

## 目标

在 canvas 页面新增一个"扩展图片节点"，**完全克隆**现有图片节点（imageGen）的全部行为，作为独立的节点类型，用于后续添加图片特殊需求功能。

## 需求

1. 新增节点类型 `imageExtGen`（简写 `imageExt`），与 `imageGen` 行为完全一致
2. 在添加节点菜单中增加"扩展图片"入口，与「图片」同分组，紧随其后
3. 所有现有图片节点功能可用：上传、生成、配置面板、工具栏（裁剪/擦除/扩展/重绘/标注/光照/3D 角度）、变换（旋转/翻转）、全屏、下载、复制、删除、分割
4. 两个节点类型独立，互不影响

## 技术约束

### 组件复用

- **禁止复制 ImageGenNode.tsx**。`imageGen` 和 `imageExtGen` 共用同一个 `ImageGenNode` 组件
- 组件内部通过 `node.type` 区分节点类型，为后续扩展预留分支入口
- 后续两种节点差异 > 30% 时再拆分独立组件

### 后端全链路兼容

- 数据库 NodeType 表新增 `key: 'imageExt'` 行（seed 脚本）
- 执行引擎管线 `topology.service.ts` 扩展类型检查，新类型复用图片节点的全部处理逻辑
- 节点创建、权限校验、生成任务分发、文件关联、导出/复制链路均放行新类型

### 跨节点操作规则

- 复制/粘贴：同类型粘贴（imageExt 复制后仍为 imageExt）
- 跨类型粘贴：数据结构一致，默认支持（保留源节点数据，仅改 type）
- 连线规则：复用现有图片节点 Handle 规则，两种节点间可正常连线，无限制

### 菜单分类

- 分类：与「图片」同分组，命名为「扩展图片」
- 排序：紧随「图片」之后
- 图标：本期复用现有图片节点图标

### 类型定义

- 不复用新的 ImageExtNodeData，直接复用 `ImageNodeData`
- 后续新增扩展字段时采用交叉类型：`ImageNodeData & { extConfig?: ExtConfig }`

## 不改动

- 现有图片节点（imageGen）的任何行为
- 现有菜单项布局（仅新增一个条目）
- 数据流结构（复用 `ImageNodeData`）
- 工具栏/配置面板组件（复用现有，不新增文件）

## 成功标准

1. 点击"添加节点 → 扩展图片"在画布上创建新节点
2. 新节点与现有图片节点行为完全一致
3. 所有工具栏操作正常（裁剪/擦除/标注/光照/3D 角度等）
4. 配置面板、图片上传/生成正常
5. 复制/删除/分割正常
6. 后端全链路（创建/上传/生成/查询/删除）通过
7. imageGen 全部功能无变更，现有测试不退化
8. **无全量复制的重复组件代码**，核心业务逻辑仅一份
