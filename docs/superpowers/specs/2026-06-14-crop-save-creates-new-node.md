# Spec: 裁剪保存改为创建新节点 + 连线

## 背景

当前裁剪保存行为（`handleCropSave`）是在原图片节点上直接替换 `fileId`，即原位替换图片。这在简单场景下方便，但后期如果多个节点都与该图片节点有连线关联，替换图片内容会破坏语义一致性。

用户要求：裁剪保存时创建**新图片节点**加载裁剪后的图片，并与原图片节点自动连线。

## 核心变更

**当前行为**：裁剪 → 保存 → 替换原节点 `fileId`（原位编辑）
**目标行为**：裁剪 → 保存 → 创建新节点（带裁剪后图片）+ 原节点 → 新节点连线

## 验收条件

### 1. canvasStore 新增 `addChildNode(sourceId, data)` 方法

- 创建与源节点同类型的新节点
- 使用智能定位（同 `addNodeWithEdge` 的碰撞检测逻辑：右侧 → 右上 → 右下）
- 新节点数据使用传入的 `data` 参数（不复制源节点数据，不设置 `transformMode`）
- 自动创建 edge：source → new node
- 返回新节点 ID

### 2. `handleCropSave` 修改

- 上传裁剪图片完成后，调用 `addChildNode` 创建新节点（携带新 `fileId`）
- 退出原节点的编辑模式
- **不再**替换原节点的 `fileId`

### 3. 副作用

- 原图片节点内容不变（保持裁剪前的图片）
- 新节点自动被选中
- 新节点位于原节点右侧（优先），避免重叠
