# 团队功能说明与操作指南

> 适用版本：2026-08 团队+协作完善（多团队/项目权限/OWNER 转让/审计日志/增量日志多实例/SV 等待/Y.UndoManager）之后的版本。

## 1. 核心概念

### 1.1 没有个人项目——一切项目都属于团队

数据模型上 `CanvasProject.teamId` 为非空字段，**每个项目必然属于一个团队**。

- 历史上的"个人项目"在一期团队化时已归入各用户的**默认团队**（注册时自动创建的「XX的团队」）。
- 所以界面上不存在"创建团队项目"或"创建个人项目"的选择——**新建的项目一律是团队项目**。

### 1.2 新建项目归属哪个团队（当前规则与边界）

新建画布时后端按**成员身份解析链**确定归属团队：

```
你最早加入的团队（joinedAt 最早的一条成员记录）
        ↓（仅当没有任何成员记录，即全新用户）
自动新建默认团队（同时发放 100 注册积分，一生仅此一次）
```

**当前边界（如实说明）**：

| 事项 | 现状 |
|---|---|
| Navbar 团队切换器 | 只切换**团队管理页**展示哪个团队，**不影响**新建项目的归属 |
| 新建项目归属 | 恒为「最早加入的团队」，无法在创建时选择团队 |
| 工作空间「我的」列表 | 按同一解析过滤：本人创建的全部 + 最早团队下他人创建的项目 |
| 团队管理页 | 没有团队级项目列表页；项目入口在画布页（见 4.6） |

即：**多团队用户目前无法把新项目建到指定团队**。此为当前产品行为缺口，后续版本可通过「创建时携带 currentTeamId」补齐。

### 1.3 多团队

一个用户可以属于多个团队、拥有多个团队（主动建团余额为 0，注册赠送只发给默认团队一次，防刷）。当前所在团队保存在浏览器 localStorage（`currentTeamId`），换设备/换浏览器不跟随。

## 2. 角色体系（两层）

### 2.1 团队层角色

| 角色 | 说明 |
|---|---|
| OWNER | 团队所有者，最高权限，每个团队至少一个 |
| ADMIN | 管理员，可管理成员/项目/查看审计 |
| MEMBER | 普通成员 |

### 2.2 项目层角色

| 角色 | 说明 |
|---|---|
| PROJECT_OWNER | 项目所有者 |
| PROJECT_EDITOR | 可编辑（画布写操作 + 执行节点） |
| PROJECT_VIEWER | 只读（可看、可评论文档内容，但写更新被服务端拒绝、执行返回 403） |

### 2.3 项目权限解析链（无显式记录时的回退）

```
显式 ProjectMember 记录（项目成员面板设置的）
        ↓ 无记录
项目创建者 → PROJECT_OWNER
        ↓ 非创建者
团队角色回退：Team OWNER → PROJECT_OWNER；ADMIN/MEMBER → PROJECT_EDITOR
        ↓ 非团队成员
无访问权限
```

也就是说：**没做过任何项目级设置时，团队 OWNER 是所有项目的所有者，其余成员都是编辑**。在项目成员面板把某人设为「只读」即写入显式记录覆盖回退值；「移除显式记录」则回到回退值。

### 2.4 权限矩阵

| 操作 | Team OWNER | Team ADMIN | Team MEMBER（项目 EDITOR） | 项目 VIEWER |
|---|---|---|---|---|
| 浏览/打开团队项目 | ✅ | ✅ | ✅ | ✅（只读） |
| 画布编辑（节点/连线/参数） | ✅ | ✅ | ✅ | ❌ 写更新被拒 |
| 执行节点/工作流 | ✅ | ✅ | ✅ | ❌ 403 |
| 模板保存为团队模板 | ✅ | ✅ | ✅ | ❌ |
| 项目成员管理（面板） | ✅ | ✅ | ❌ | ❌ |
| 授予项目 OWNER | ✅ | ❌（防绕过） | ❌ | ❌ |
| 团队成员管理/配额 | ✅ | ❌ | ❌ | ❌ |
| 查看审计日志 | ✅ | ✅ | ❌ | ❌ |
| 转让团队所有权 | 仅 OWNER | ❌ | ❌ | ❌ |
| 解散团队 | 仅 OWNER | ❌ | ❌ | ❌ |

保护性规则：
- **移除最后一个显式项目 OWNER 被拒绝**（保证显式所有权链不断）。
- 团队 ADMIN 不能把成员设为项目 OWNER（只有项目 OWNER 或团队 OWNER 可以）。
- 团队角色只能设为 ADMIN/MEMBER，不能通过改角色造出第二个团队 OWNER（转让是唯一途径）。

## 3. 实时协作能力

| 能力 | 说明 |
|---|---|
| 多人实时编辑 | 同项目多人同时编辑实时互见（Yjs CRDT），支持服务端多实例部署（Redis 中继） |
| 在线状态 | 顶栏在线头像 + 远端光标（带用户名标签）跨实例可见 |
| 只读连接 | VIEWER 打开项目可看不可改——服务端在 WebSocket 鉴权时置只读，写更新直接拒绝 |
| 撤销（Ctrl+Z / 重做 Ctrl+Shift+Z） | 只撤销**自己的**操作：他人/AI 的写入不入撤销栈，不会"撤销掉别人的编辑" |
| 撤销粒度 | 连续输入自动合并（约 0.5 秒窗口）、拖拽/缩放一次手势一项、手动分隔在交互边界自动生效 |
| 撤销栈上限 | 100 项；刷新页面后清空（撤销历史是内存态，不跨会话） |
| 执行读新参数 | 改参数后立即点执行，服务端按状态向量等待同步，不会用旧参数执行（毫秒级窗口已消除） |
| 崩溃安全 | 增量日志 + 快照（Postgres 权威），对等实例 5 秒防抖窗口内的数据也有跨实例拉取兜底 |

## 4. 操作指南

### 4.1 团队切换 / 新建团队（顶栏 Navbar）

- 登录后 Navbar 右侧显示**当前团队名**按钮，点开：
  - 团队列表（当前团队带 ✓）——点击切换（整页刷新生效）
  - **新建团队**——输入名称创建，创建后自动切换过去
- 新建团队余额为 0、无赠送积分（注册赠送一生只发一次）。
- 解散团队后若当前团队失效，刷新会自动回退到列表中第一个团队。

### 4.2 团队管理页（/team）

顶部概览卡：团队名/角色/席位（如 2/20）/存储用量（如 6.0G 上限）/剩余积分/订阅到期时间。

五个 Tab：

| Tab | 内容与操作 |
|---|---|
| 成员管理 | 成员表（角色/月度配额进度）；行操作：**改角色**（ADMIN/MEMBER）、**转让所有权**、**配额度**、**移除**；右上「邀请成员」 |
| 积分管理 | 积分流水表；**充值**按钮（1 元 = 10 积分）；**开通团队订阅**（档位选择） |
| 权限设置 | 「加入需审批」开关——关闭后邀请链接直达入团 |
| 加入申请 | 待审批列表：通过/拒绝（需开启审批） |
| 审计日志 | 仅 OWNER/ADMIN 可见；分页倒序展示团队操作历史（见 4.7） |

### 4.3 邀请成员

1. 成员管理 Tab → 「邀请成员」→ 弹窗内复制**邀请链接**发给对方。
2. 对方打开链接（未登录会先跳登录）→ 填写留言提交申请。
3. 开启审批时：团队 OWNER/ADMIN 在「加入申请」Tab 通过/拒绝；关闭审批时直接入团。
4. 重复申请会得到提示。

### 4.4 转让团队所有权

1. OWNER 在成员管理 Tab 找到目标成员行 → 点「**转让所有权**」。
2. 确认弹窗（提示自己将降为 ADMIN）→ 确定。
3. 结果：目标成员成为 OWNER（概览卡角色、成员表、审计同步更新），原 OWNER 变为 ADMIN。

### 4.5 成员配额（月度生成额度）

成员行「配额度」可设置该成员的月度生成配额（0 = 不限），成员表显示当月用量进度。

### 4.6 项目成员管理（项目级权限）

1. 打开任一画布项目，顶部项目名旁点「**成员**」按钮。
2. 面板列出**全团队成员**及其有效项目角色：
   - **来源=继承**：未做显式设置，按解析链回退（创建者→OWNER、其余→EDITOR）
   - **来源=显式**：已设置过覆盖记录
3. 行操作菜单：
   - **设为编辑 / 设为只读 / 设为所有者**——写入显式覆盖（对继承成员同样可用）
   - **移除显式记录**——删掉覆盖回到回退值（继承成员此菜单项禁用；移除最后一个显式 OWNER 会被拒绝）
4. 「添加成员」仅列出**继承**状态的成员（避免对已显式成员重复设置）。

### 4.7 审计日志

记录团队级敏感操作，供 OWNER/ADMIN 追溯：建团、解散、成员变更（改角色/移除/配额）、加入审批、转让所有权、充值、订阅/到期、项目成员三类操作。每条含操作者、时间、对象、变更前后值。

### 4.8 只读访问的体验

被设为「只读」的成员打开项目：
- 画布正常浏览、能看到他人实时编辑；
- 任何写操作**静默无效**（服务端拒绝该连接的更新，不弹错误）；
- 点执行会收到「无项目编辑权限」错误提示。

## 5. 积分与订阅

- 团队共享积分池（充值积分 + 订阅积分分开记账），执行消耗团队积分。
- 充值：1 元 = 10 积分，微信扫码支付（**注意：充值二维码弹窗接线为已知未完成项，支付链路在开发中**）。
- 订阅：档位开通，含席位/存储等权益。
- 注册赠送 100 积分仅随默认团队一次性发放；主动建团不发放。

## 6. 常见问题

**Q：我在哪创建"团队项目"？**
A：没有单独入口——工作空间点新建画布即是。当前它会归属到你**最早加入的团队**（见 1.2 边界），多团队用户暂无法选择归属。

**Q：切换团队后工作空间内容会变吗？**
A：不会。「我的」列表 = 本人创建的全部项目 + 最早团队的项目，与切换器无关。

**Q：为什么我 Ctrl+Z 撤销不了别人的操作？**
A：设计如此——撤销栈只含你自己的操作（含 AI 代你执行的写入按远端处理，不入栈）。

**Q：刷新后为什么撤销不了之前的操作？**
A：撤销历史是浏览器内存态，刷新即清空；画布内容本身由服务端持久化，不受影响。

**Q：项目创建者和团队 OWNER 是一回事吗？**
A：不一定。项目创建者始终是该项目的 OWNER（显式或回退）；团队 OWNER 对团队内所有项目拥有所有者权限；团队 ADMIN 是所有项目的编辑者 + 可在项目成员面板做管理（但不能授予项目 OWNER）。

**Q：如何让某人只能看不能改？**
A：项目成员面板（画布页「成员」按钮）→ 该成员行「管理」→「设为只读」。恢复用「设为编辑」或「移除显式记录」。
